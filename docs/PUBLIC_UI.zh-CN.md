# 0.3.0-alpha.2 用户界面调整

本次仅修改插件图标、界面内容和布局，不改变配套固件或 USB 后台协议，不重新刷写 M5。

## 内容原则

默认页面保留用户完成操作所需的信息：设备名称与局域网连接、首次绑定入口、固件版本、升级兼容范围、备份与断电提醒、实际错误原因以及按键说明。

下载地址、完整 SHA、源码与许可、运行平台及诊断代码放入默认收起的「高级与开源信息」。个人测试反馈、暂停测试、采集字节计数及 SDK 基线不在日常页面展示，原始范围和历史证据继续保留在检查文档中。折叠技术信息不等于隐藏失败原因，也不改变真实的 LAN 和现有布局限制。

## 图标

用户提供的产品图片用于插件头像、主导航与页头。包内 WebP 保留透明背景，512×512、130,292 B，原图和图标摘要见[图标说明](../assets/README.md)。宿主按官方规则转换为 data URL，iframe 无需额外资源请求。

workspace 专属页面导航和设置导航遵循官方命名线图标要求；不修改 Studio 核心或 SDK 来替换这些受限位置。

## 发现与处理

| 严重性／置信度 | 问题与处理 |
|---|---|
| 中／高 | 原图1,260,852 B超过官方256,000 B单图标限制，直接作为安装图标会失败；已制作满足上限的透明WebP并加入分发清单。 |
| 中／高 | iframe的img-src只允许data/blob，包内相对路径不能直接用于页头；改用宿主归一化后的ctx.plugin.icon，并为非法或加载失败的图片保留文字页头。 |
| 中／高 | 默认固件页把开发验收、个人测试与升级操作混在一起；用户操作放在前面，历史与测试移至文档，校验和开源材料默认折叠。 |
| 低／高 | 默认展示Node/平台、错误代码和长SHA增加阅读负担；技术信息折叠，失败时仍显示可读的真实原因，未知错误不伪装成功。 |
| 低／高 | 空闲时刷新与取消按钮没有可执行任务；按现有状态显示，错误时保留重试，写入阶段继续禁止用户取消。 |
| 低／高 | 实际宿主以main作为iframe挂载根，插件再次创建main会产生嵌套主内容地标；内部改用有类名的内容容器，浏览器夹具同步真实根节点并验证没有嵌套main。 |
| 低／高 | 真实页面中进度条的display:block覆盖了原生hidden样式，空闲时仍出现灰条；组件统一尊重hidden状态，并以浏览器可见性回归验证空闲进度条隐藏。 |
| 范围限制／高 | 主导航和插件头像支持图片，workspace/settings专属导航只能命名线图标；遵循官方规范，没有为外观修改核心。 |
| 范围限制／高 | 原机首刷、跨网远程、其他平台和未完成的实体矩阵不由界面精简变成支持或通过；必要提醒保留。 |

本版主机、浏览器、实际安装和图片加载结果另存脱敏证据，不能将0.3.0-alpha.1的实机烧录记录计作本版重新烧录。
